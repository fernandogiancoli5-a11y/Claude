Why Pairloom

Coding agents are built for one person at a keyboard.

When an agent writes code, the rest of the team usually sees the result, not the work: a pull request that appears out of nowhere, a terminal session nobody else could follow, and decisions nobody else got to weigh in on.

Pairloom puts the agent in a room the whole team can see into. The work streams live to everyone, changes stay on their own branch, and a person stays responsible for every step that matters.

How it works

From request to merged change, with people in the loop.

  1. 1

    Start a task

    Describe what to build. The agent gets its own git branch, isolated from your main branch and from every other task.

  2. 2

    Watch it together

    Every file read, edit and command streams live to the whole team, in any browser. Closing yours doesn't stop the agent.

  3. 3

    Steer and approve

    Teammates propose instructions; the task's host approves them before the agent sees them, and decides on any command that needs permission.

  4. 4

    Verify, review, merge

    Pairloom runs your project's tests itself. Reviewers read the real diff, approve, and only then can the host merge.

The product

One screen for the agent's work and the team's decisions.

Review that means something

Changes appear as a real git diff when the agent's turn ends. A readiness checklist shows whether the work is final, whether tests passed on exactly these changes, and who approved — and merging stays locked until someone does.

  • Tests are run by Pairloom, not reported by the agent
  • Approvals are tied to the exact change set
  • A newer change from the agent needs a fresh review

Your team's work at a glance

The dashboard shows every project you belong to, its latest task, whether its worker is online, and anything waiting on you — approvals to give and changes to review.

  • Teams with owner, collaborator and viewer roles
  • Single-use invite links
  • Access enforced by the server, not just hidden in the UI

Built to be trusted

The agent works for the team, on terms the team sets.

Your code stays with your worker

The agent runs in a small worker process next to a clone of your repository — on a teammate's machine or your own server. Collaborators never get shell access to it.

Risky actions wait for a person

File edits can be auto-accepted on the task branch; deleting files and running arbitrary commands need the host's approval. Network tools are refused.

Survives the real world

Interrupt a turn at any time. If the worker restarts mid-task, Pairloom says so plainly and the host can resume from the saved transcript.

FAQ

Straight answers.

Is Pairloom available now?

It's in early access. The core workflow — shared tasks, approvals, independent test runs, review and merge — works today, and we're onboarding small teams from the waitlist.

Which AI model does it use?

Today the agent runs on openai/gpt-oss-120b hosted by Groq, using your own API key on your worker. Pairloom's agent harness speaks the OpenAI-compatible API, so other providers are a configuration change rather than a rewrite.

Where does my code run?

On the worker you connect: a process with its own clone of your repository. The Pairloom server coordinates the team and stores the task history; the worker dials out to it.

What isn't there yet?

Merges currently land on the worker's local branch; pushing to GitHub and opening pull requests is not built yet. Invitations are links you share yourself (no email delivery), and there's no password reset yet.

What happens to my email address?

We store it with the time you signed up (and your role, if you choose one) so we can invite you. Nothing else. Read the privacy note.
